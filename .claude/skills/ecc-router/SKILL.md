# ECC Skill Router

You have access to a 296-skill library under `.claude/skill-library/<skill-name>/SKILL.md`. 287 skills are vendored from https://github.com/affaan-m/ECC/tree/main/skills (healthcare/HIPAA skills excluded). An additional 9 skills were pulled from individual repos surfaced via https://github.com/quemsah/awesome-claude-plugins to cover LLM fine-tuning, agent-driven optimization, and SQL-schema-to-semantic-context work not present in the ECC set (see note at the bottom of the index). These skills are NOT auto-listed in your available-skills system reminder on purpose, to avoid paying ~296 extra description entries of context on every single turn. This router is the single entry point that keeps that cost at zero until a matching task actually shows up.

## Procedure

1. Scan the index below for the skill(s) whose description best matches the current task.
2. If one or more clearly match: `Read` that skill's `SKILL.md` (and any supporting files it references, from the same folder) and follow its instructions directly. You do not need the `Skill` tool for these — reading the file and following it is equivalent and cheaper.
3. Only read the specific skill(s) that match. Do not read others 'just in case'.
4. If nothing matches well, say so and proceed with your own best judgment rather than forcing a fit.
5. If 2-3 skills are close matches for a multi-part task, it's fine to read more than one, but prefer the smallest set that covers the task.

## Non-ECC additions (9 skills, sourced individually)

The skills below were not part of the ECC library. They were pulled from repos surfaced via the https://github.com/quemsah/awesome-claude-plugins catalog to cover three gaps the ECC set didn't address well: LLM fine-tuning, agent-driven black-box optimization, and turning a SQL schema into structured semantic context. General agent-orchestration/harness ground was already covered extensively by the ECC `agent-*`/`agentic-*`/`autonomous-*` skills above, so this batch stayed narrow rather than duplicating that.

- `unsloth-buddy` (from `TYH-labs/unsloth-buddy`) — fine-tuning/RL (SFT, DPO, GRPO, ORPO, KTO, SimPO) with the Unsloth library. Includes `sub-skills/`, `scripts/` (training templates, dashboards, Colab helpers), and `eval/`.
- `optim-agent` (from `Optim-Agent/optim-agent`) — the agent itself acts as the sampler in a black-box parameter-optimization loop (model training, inference, quant strategies, RL, scientific workflows). Requires `pip install optim-agent`. Single-file skill.
- `context-engineering-bootstrap`, `context-engineering-dataset-generation`, `context-engineering-evaluate`, `context-engineering-hillclimb`, `context-engineering-init`, `context-engineering-workflow`, `context-generation-guide` (from `GoogleCloudPlatform/db-context-enrichment`) — turn a database schema + relationships into a structured "ContextSet" (templates, facets, value searches) for accurate NL-to-SQL/GQL generation, with per-dialect reference guides (Postgres, MySQL, Spanner GoogleSQL/PostgreSQL, AlloyDB, Bigtable, Firestore). Note: the save/validate/evaluate steps (`mutate_context_set`, `validate_context_set`, Evalbench) assume Google's own MCP server tools are connected — without that server, use these skills for the schema-to-context methodology and dialect references, not the automated pipeline.
